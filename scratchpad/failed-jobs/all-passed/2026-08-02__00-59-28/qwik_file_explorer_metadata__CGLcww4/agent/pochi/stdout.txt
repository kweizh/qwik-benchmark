# Server-Side File Explorer with Metadata in SQLite ## Background Create a server-side file explorer application using the Qwik framework (Qwik City meta-framework). The application must allow users to upload files, list all uploaded files with their metadata stored in a local SQLite database, and delete files from both disk storage and the database. ## Requirements * **Project Structure & Routing**: * The Qwik City application must be located at `/home/user/qwik-app`. * Serve a user interface at the `/files` route. * Expose the following API endpoints: * `POST /files/upload`: Handles multipart form uploads. * `GET /files/list`: Returns JSON metadata of all uploaded files. * `DELETE /files/:id`: Deletes a file by its database ID. * **File Upload (`POST /files/upload`)**: * Accepts a `multipart/form-data` request. * The form fields must include: * `file`: The binary file to upload. * `tag`: A string tag/category for the file (e.g., "documents", "images"). * Saves the uploaded file to disk in the directory `/home/user/qwik-app/public/uploads`. * Extracts and stores file metadata in a local SQLite database at `/home/user/qwik-app/metadata.db`. * Response on success: HTTP status `201 Created` with a JSON object representing the newly created record: ```json { "id": 1, "name": "example.txt", "size": 1024, "mime": "text/plain", "tag": "documents" } ``` * If the file is missing or invalid, returns HTTP status `400 Bad Request` with a JSON error message `{"error": "..."}`. * **File Metadata Storage (SQLite)**: * Database location: `/home/user/qwik-app/metadata.db`. * Table name: `files`. * Schema columns: * `id` (INTEGER, PRIMARY KEY, AUTOINCREMENT) * `name` (TEXT, NOT NULL) - the original file name. * `size` (INTEGER, NOT NULL) - file size in bytes. * `mime` (TEXT, NOT NULL) - MIME type of the file. * `tag` (TEXT, NOT NULL) - the tag provided during upload. * **File Listing (`GET /files/list`)**: * Fetches all records from the SQLite `files` table. * Response: HTTP status `200 OK` with a JSON array of file metadata objects: ```json [ { "id": 1, "name": "example.txt", "size": 1024, "mime": "text/plain", "tag": "documents" } ] ``` * **File Deletion (`DELETE /files/:id`)**: * Deletes the file matching the specified integer `id` from the disk storage directory `/home/user/qwik-app/public/uploads`. * Deletes the corresponding metadata record from the SQLite database. * If deletion is successful, returns HTTP status `200 OK` with JSON `{"success": true}`. * If the file ID does not exist in the database, returns HTTP status `404 Not Found` with JSON `{"error": "..."}`. * If the file record exists in the database but the physical file is missing from disk, it must still delete the database record and return HTTP status `200 OK` with JSON `{"success": true}`. * **User Interface (`/files` page)**: * Serves an HTML page with the following elements: * An upload form with `id="upload-form"` containing: * A file input element with `id="file-input"` (or `name="file"`). * A text input element with `id="tag-input"` (or `name="tag"`). * A submit button. * A container element with `id="file-list"` that displays the list of uploaded files with their name, size, mime, and tag. * Each listed file must have a delete button with the attribute `data-id` set to its database ID or a class of `delete-btn`, which triggers the file deletion when clicked. ## Implementation Hints * Project path: `/home/user/qwik-app` * Start command: `npm run dev` * Port: 3000
